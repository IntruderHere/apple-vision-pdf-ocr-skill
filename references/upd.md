# Реквизиты УПД (универсальный передаточный документ)

Где искать ключевые поля на скане УПД после OCR — для задач вида
«сопоставить документы с адресатами/объектами, выписать суммы».

## Поля

- **Назначение / основание передачи**: поле «Основание передачи (сдачи) /
  получения (приемки)» — строка вида `Договор №… от … (Комплект №N …)`:
  номер и дата договора, в скобках — назначение комплекта. В двухстраничных
  УПД строка часто на 2-й странице (нижняя часть), на 1-й — только подпись
  поля «(5) договора (соглашения) (при наличии):».
- **Сумма**: строка «Всего к оплате (9)» — последняя строка таблицы позиций.
  Читать `scripts/vision_table_row.py --label "Всего к оплате" --page <0|1>`
  (`--page` 0-based: 0 — первая страница, 1 — вторая).
  Клетки слева→направо: стоимость без налога → «акциза»/НДС → итого с налогом.
- **Шапка**: продавец (ИП/ООО + адрес) и покупатель — реквизиты сторон не путать
  с номером и датой договора из «Основания передачи».

## Верификация и отчёт

- Сумма: «без налога + НДС = итого с налогом» — если сходится во всех
  документах, цифры прочитаны верно, crop_ocr не нужен.
- Банд-чтение строки подхватывает клетки соседних строк (последняя позиция
  над итоговой) — выбирать арифметически сходящуюся тройку, не левую.
- Однотипные комплекты часто с идентичными суммами (одинаковые позиции и
  количество) — расхождение с этим паттерном сигнал ошибки OCR.
- Устойчивый сценарий для пользователя: идентификаторы задаются отдельным
  перечнем, соответствие 1:1 (N документов ↔ N идентификаторов) — при совпадении
  всего перечня дополнительно доверять; при лишнем/недостающем — перепроверить
  банд-чтение.
- Формат результата: таблица (файл | контрагент | сумма) и, если нужно,
  переименование файлов «…_<идентификатор>.pdf». Отчёт на русском, суммы в
  форматах документов (пробел-разделитель тысяч, запятая-дробная).
